# Security-test evidence record

Use one record per finding or abuse case. Keep real sensitive evidence in an approved restricted system; commit only sanitized examples.

- Test date and owner:
- Written authorization and scope reference:
- Application commit and deployed artifact identifier:
- Tool version, image digest, rule/add-on version:
- Target environment and allowed routes:
- Tested roles/tenants and confirmation of valid session (no credentials):
- Threat / expected invariant:
- Test input or sanitized reproducer:
- Expected result:
- Observed result and side-effect check:
- Source finding, runtime finding, manual finding, or analyzer error:
- Coverage reached and coverage not reached:
- Reproduction result before repair:
- Repair commit and deployment reference:
- Retest result after repair:
- Remaining risk / compensating control:
- Exception approver and expiration, if applicable:
- Restricted evidence location and retention date:
- Release decision and accountable owner:

An empty field is a gap to investigate, not a default pass.
